# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

Toomu is a Flutter app for Android and Windows (no iOS/macOS): YouTube/TikTok/web video downloader, ad-free YouTube player, music player and 1DM-style in-app browser that catches media on any page.

## Commands

```bash
flutter pub get
flutter analyze                                   # CI fails on any issue (flutter_lints)
flutter test                                      # unit tests in test/ (~20 s; timers are shortened in tests via @visibleForTesting statics)
flutter test $(tool/test_shard.sh 0 3)            # one CI shard (0..2 of 3)
flutter test test/windows_ytdlp_test.dart         # one file
flutter test test/windows_ytdlp_test.dart --plain-name "drops the Android aria2c option"   # one test
tool/build_release.sh                             # release APKs per ABI (arm64, armv7), obfuscated
flutter build windows --release                   # Windows x64 (needs a Windows PC with Visual Studio's C++ workload)
```

- CI (`.github/workflows/build.yml`, Flutter 3.41.1): push to `main` builds the arm64 APK (armv7 too on tags) and Windows x64 as a zip plus an Inno Setup installer (`windows/installer/toomu.iss`; the Windows job attaches both to the release when done), while parallel jobs run `flutter analyze`, the Dart tests split by file into 3 shards (`tool/test_shard.sh`, all CPU cores each) and the Kotlin tests; every successful main build publishes a GitHub Release under a new tag (`vYYYY.MM.DD-HHMM`, Bangladesh time); a pushed `v*` tag publishes one under that tag with armv7 too.
- `--dart-define=TOOMU_BUILD=...` labels the build in Settings → Diagnostics.
- Release signing: `android/key.properties` or `ANDROID_KEYSTORE_*` env/secrets; otherwise the debug key.
- The Gradle `merge*NativeLibs` tasks run `tool/trim_ytdlp_bundles.py` (needs `python3`; skipped with a warning if missing) to strip unused files from yt-dlp's bundled Python/FFmpeg archives.
- Debug builds package only `arm64-v8a` (add `x86_64` in `android/app/build.gradle.kts` for Intel emulators).

## Bug fixes

Every fix ships with a regression test so the issue can't come back: write the test first, run it and see it fail for the reported reason, then fix and see it pass. Name the test after the symptom (e.g. `'grey top bar does not return after reopening'`) and keep it in `test/` (Kotlin: `android/app/src/test/`). If a bug truly can't be reproduced in a test (device-only, CI config), say so in the commit message. Changes that only remove something (a feature, a notification) need no test.

## Architecture

**GetX everywhere.** App-lifetime services are registered in `lib/app/services/app_services.dart` in dependency order (some in parallel; anything used by another service's `init` must come first). Feature modules live in `lib/app/modules/<feature>/{bindings,controllers,views}`; routes in `lib/app/routes/app_pages.dart`, main tabs in `modules/home/home_tabs.dart`. Persistence is GetStorage via `StorageService`; settings in `SettingsService` with keys in `core/values/app_constants.dart`.

**Native layer via method channels named `toomu/*`.** Android (`android/.../MainActivity.kt` and siblings): `toomu/ytdlp` (+ `toomu/ytdlp/progress` events) → `YtDlpBridge.kt` (youtubedl-android: yt-dlp + Python + QuickJS + FFmpeg + aria2c, run as executables, hence `useLegacyPackaging` and minSdk 24), plus `download_notify`, `media_library`, `media_scanner`, `video` (PiP/background play), `intents` (share/open-with), `bubble` (floating button), `update` (self-install). Windows has no native channels of its own: `YtDlpBridge` switches to `WindowsYtDlp` (`data/providers/ytdlp/windows_ytdlp.dart`), which downloads `yt-dlp.exe` from GitHub on first launch (FFmpeg + Deno follow in the background; downloads wait for FFmpeg, lookups don't), runs it with `Process`, kills the process tree on cancel and updates it daily like the Android bridge; no aria2c (`--toomu-aria2c` is dropped). Dart guards Android-only features with `Platform.isAndroid`; Windows decisions go through `HostOs` (`core/utils/host_os.dart`: `isWindows`, `hasYtDlp`, …), whose `override` lets tests on the macOS/Linux host check the Windows path. `WindowsYtDlp` takes its folder, GitHub URL, launcher, unzip and kill steps as parameters; `test/windows_ytdlp_install_test.dart` drives it against a local fake GitHub with a shell-script yt-dlp. On Windows: just_audio plays through `just_audio_media_kit`, `audio_session`/`just_audio_background`/`open_filex` are skipped (files open via Explorer, `core/utils/shell_open.dart`), downloads go to `%USERPROFILE%\Downloads\Toomu`, and the window opens phone-shaped (430×860, min 360×600, `windows/runner/`).

**YouTube.** `YoutubeProvider.fastLinks` is a fast lookup without yt-dlp (~0.3 s, whole-file links when available); `YtDlpService` is the fallback and the Android downloader, auto-updating yt-dlp from GitHub daily, with extra args from remote config. `StreamProxy` (127.0.0.1) sits between players and YouTube: it slices requests into ≤ ~10 MB `range=` pieces (YouTube throttles or 403s large ranges), matches the link's IP version, and swaps fast-lookup links for yt-dlp's mid-playback. Android yt-dlp downloads are routed through it too (`routeInfoJson`).

**TikTok tab (`modules/tiktok`).** TikTok-style "Following | For You" (`TiktokFeeds`; two `TiktokController`s tagged `foryou`/`following`, each with its own page, playback and downloads ahead), ad-free; pull to refresh / double tap on the feed's name (`reset`), the nav shows TikTok's note (`AppNavItem.logoPath`), seek bar (`views/tiktok_seek_bar.dart`), a loading page after the last video that plays the first new one when it comes. Sign-in: `TiktokSignInPage` (TikTok's login, same UA) → `TiktokAccountService` (signed in = `sessionid` cookie; user from the page's `webapp.app-context.user`); the WebView cookies make For You personal and feed Following (`/following`, its feed request unverified: a visitor's Following page has no videos), and feeds start over on sign-in/out. A video counts as started when, after mpv's new-file buffering signal, buffering goes off or the first position above zero comes (`SessionTiktokPlayback.started`; mpv keeps the old position until the new file's first frame, and from a playing video to a fast one its idle flag flips too quickly for "buffering off" to be reported). `WebTiktokFeedSource` (`data/providers/tiktok/tiktok_feed.dart`) loads tiktok.com/foryou in a WebView kept in the tab under the opaque feed (texture, not hybrid composition, which made swiping stutter; desktop UA = `TiktokService.agent`, no account; not headless: Android's headless WebView is invisible, draws no frames, and TikTok then never loads past its first 2 videos); its injected `feedJs` copies the page's embedded first videos and every answer of TikTok's own signed `/api/recommend/item_list` calls out, keeps the page's players silent, and `__toomuMore()` scrolls TikTok's feed to load the next batch. `TiktokItem.fromJson` drops ads/slideshows and picks the best H.264 file; videos play in the shared `VideoSessionService` player straight from TikTok's CDN (`TiktokService.playHeaders`), looped, only while the tab is shown and the app is open; The next video opens when a swipe settles (`settled`, not half way through it), with a stiffer snap (`TiktokSwipePhysics`). `TiktokPrefetch` loads the first ~4 s (range request, 256 KB–2 MB) of the next 4 once the current one plays (temp `tiktok_ahead/`, last 8 kept); `TiktokHeadServer` (127.0.0.1) plays them: the head's bytes from the file, the rest from TikTok with the same range (a seek past the head goes straight to TikTok). The page pauses (Android `pause`) while the tab isn't shown, plus `pauseTimers` while the app is hidden, and closes 2 min after leaving the tab. Save = `enqueueTiktok` (yt-dlp, no watermark). Comments and likes (signed in; TikTok answers visitors' comment requests with an empty body): `WebTiktokVideoPage` (`data/providers/tiktok/tiktok_video_page.dart`, one more WebView under the feeds) opens the video's page, its `pageJs` copies `/api/comment/list`, `/reply`, `/api/commit/item/digg` and `/api/comment/digg` answers out and presses TikTok's own buttons (`like-icon`/`comment-icon`; a comment found by its text): Toomu never builds TikTok requests. `TiktokActions` (heart, double tap = like only) and `TiktokCommentsController` turn red at once and go back if TikTok's answer refuses; the sheet is `views/tiktok_comments_sheet.dart`. Comment markup and the reply/digg parameter names couldn't be seen as a visitor (unverified).

**Downloads (`DownloadService`).** One queue, sources in `DownloadTask.source`:
- `youtube`: yt-dlp (fast-lookup info JSON first, client fallbacks after).
- `direct`: own engine, 10 MB chunks over N connections, resumable, end-game splitting of the slowest piece; browser downloads carry the page's User-Agent/Referer and fresh WebView cookies.
- `tiktok` / `stream`: yt-dlp on the URL (HLS/DASH manifest or page).
- Network errors mark a task "Connection lost" and it auto-resumes when a real connection works again; expired browser links offer "Refresh link" (reopens the page in `BrowserController` with the task and matches the recaptured file).
- Partial data of yt-dlp tasks lives in `YtDlpService.workRoot/<taskId>`; direct tasks use `<file>.part` (+ `.chunks/`).

**In-app browser (`modules/browser`).** Chrome-like and tabbed: `BrowserSession` (route controller) owns the tabs, one `BrowserController` per tab (tag = tab id); `tab_session.dart` holds the pure tab rules (order, opener, the last 4 pages kept loaded, 2 on low-end phones, others reload when shown). Tabs, history and bookmarks persist in `BrowserStore` (own GetStorage box `browser`; pure rules in `browsing_data.dart`). The new-tab page (`toomu://newtab`) is a Flutter screen; `address.dart` has what the bar shows (just the site), URL-vs-search, and suggestion merging (bookmarks, history, Google suggest). ⋮ menu (`browser_menu.dart`), tab switcher, History/Bookmarks pages, find in page and pull to refresh (Android), Desktop site, long-press link and image menus (`link_menu.dart`, `image_menu.dart`). On Android 7–9 a page that fails for a non-network reason shows why (`engine_notice.dart`: no more WebView updates there). Each tab's page is an InAppWebView with an injected script (`media_sniffer.dart`, runs in all frames) that reports media candidates to `MediaCapture`, which probes, parses HLS/DASH qualities (`core/utils/media_manifest.dart`), drops segments/tiny files and marks DRM; the result shows in `views/media_sheet.dart`. `redirect_guard.dart` blocks ad redirects/popups (popups load in the same tab, so all go through `shouldOverrideUrlLoading`): a cross-site jump right after a tap not on a link to that site, or any navigation to a host on the downloaded blocklist (StevenBlack hosts + gambling, refreshed weekly). Ad resources aren't blocked: the plugin's Android content blocker sends a HEAD request per resource. On Android the page is paused (`pause` + process-wide `pauseTimers`) while the app is hidden or Toomu's player is open over it. The top bar's downloads button (`views/downloads_sheet.dart`) shows progress and the download list in a sheet so the page stays open. `extractors/` handles pages with a dedicated flow (YouTube, direct file links).

**App updates (Android).** CI passes the release tag as `--dart-define=TOOMU_TAG`; `UpdateService` checks GitHub's latest release (daily, and Settings → Check for updates), downloads the APK for the phone's ABI and installs it through a `PackageInstaller` session (`toomu/update` → `UpdateReceiver.kt`, `REQUEST_INSTALL_PACKAGES`); on Android 12+ only the first update asks for confirmation, later ones are silent because Toomu is then the installer of record. Builds without a tag (local/dev) never auto-check. Phones only accept an update signed with the same key, so CI needs the `ANDROID_KEYSTORE_*` secrets.

**Remote config.** `RemoteConfigService` fetches a static JSON at startup (shape in `remote_config.example.json`): yt-dlp args/channel, connections, start-page sites, feed categories, browser blocklist URL; every field optional.
